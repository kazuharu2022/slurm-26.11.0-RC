# SMD-103 HOME/workdir境界

- 状態: `PASS`
- 対象: Apple M5 Max / arm64 / macOS上の`slurmd`・`slurmstepd`
- Slurm: `26.11.0-0rc1`
- test user: `testuser`（UID/GID 3001:3001）
- production設定変更: なし
- package導入: なし

## Research Question

macOS worker上のbatch jobで、Slurmは実行userのHOMEを維持し、許可された通常path、`/tmp`、
空白・日本語を含むpathを指定workdirとして使用できるか。また検索権限のないroot専用pathを
誤って使用せず、既存の`/tmp` fallbackへ安全に移行できるか。

## source確認

`src/slurmd/slurmstepd/mgr.c`の非container経路は、user権限へdropした後で`step->cwd`へ
`chdir()`する。失敗時は`couldn't chdir ... going to /tmp instead`を記録し、`/tmp`への
`chdir()`も失敗した場合だけstepを終了する。SMD-007でも不存在pathから`/private/tmp`への
fallbackを確認済みだが、EACCES、user HOME、空白・日本語pathは未測定である。

## 試験case

| case | 要求workdir | 期待結果 |
|---|---|---|
| `home` | Directory Serviceが返す`testuser` HOME | HOMEとcwdが`/Users/testuser`、stderr空 |
| `tmp` | `/tmp` | HOME維持、物理cwdが`/private/tmp`、stderr空 |
| `unicode` | run directory内の`work dir-日本語` | 空白・日本語を失わず指定pathで実行、stderr空 |
| `denied` | root所有0700の専用test directory | EACCESと`/tmp` fallbackを記録し、root-only markerは読めない |

全caseは`testuser`、1 CPU、128 MiB、1分上限でbatch jobを1件ずつ、合計4件投入する。
payloadはidentity、HOME、物理cwd、固定markerだけを出力し、環境全体やHOME内のfile名・内容は
出力しない。既存HOME、production config、daemon、account recordは変更しない。

## 成功条件

1. 全4 caseで実user/UID/GIDが`testuser`/3001/3001、HOMEが`/Users/testuser`である。
2. 許可された3 pathは指定した物理cwdで実行され、stderrが空である。
3. denied pathは`Permission denied`と`going to /tmp instead`を記録し、cwdは`/private/tmp`となる。
4. denied payloadからroot-only directoryをsearchできず、markerをreadできない。
5. 全jobとbatchが`COMPLETED 0:0`となり、stdout/stderr ownerが3001:3001である。
6. 終了後はnode `IDLE`、CPU/memory割当0、queue・`slurmstepd`・関連process残留0である。
7. slurmd PIDとproduction config/payload hashが前後一致する。

denied caseでjobが成功するのは、無許可directoryの利用成功ではなく、Slurm sourceどおり
`/tmp`へ安全にfallbackした場合だけである。denied directoryへ入れた場合はFAILとする。

## 実測結果 — PASS

2026-09-12 00:07 JST、Jobs 447～450で4 caseを実行した。

| case | Job | 要求cwd | 観測した物理cwd | stderr | accounting |
|---|---:|---|---|---|---|
| `home` | 447 | `/Users/testuser` | `/Users/testuser` | 空 | job/batch `COMPLETED 0:0` |
| `tmp` | 448 | `/tmp` | `/private/tmp` | 空 | job/batch `COMPLETED 0:0` |
| `unicode` | 449 | `work dir-日本語` | 同じ空白・日本語名を含む`/private/tmp/...` | 空 | job/batch `COMPLETED 0:0` |
| `denied` | 450 | root所有0700 directory | `/private/tmp` | EACCESとfallbackを2行記録 | job/batch `COMPLETED 0:0` |

全jobで`job_user`・実userは`testuser`、UID/GIDは3001:3001、HOMEは`/Users/testuser`だった。
denied caseではpayload自身もroot-only directoryをsearchできずmarkerをreadできないことを確認し、
`denied_directory_access=BLOCKED`を記録した。これは無許可pathでの実行成功ではなく、
`slurmstepd`が同じEACCESをbatch/step準備の2経路で記録して`/tmp`へfallbackした結果である。

stdout/stderrは全件3001:3001、mode 0644。最終nodeは`IDLE`、CPU/memory割当0、`AllocTRES`空、
queue空、`slurmstepd`と関連processの残留なし。slurmd PIDは94504を維持し、production configと
payloadのhashは前後一致した。

## 結論

今回のlocal APFSと`/tmp`範囲では、HOME保持、通常path、`/tmp`の物理path、空白・日本語path、
EACCES時の安全fallbackが一貫して動作したため、SMD-103を`PASS`とする。
