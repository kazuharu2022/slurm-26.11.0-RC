# SMD-404 configless

- 状態: `PASS`
- controller: `ubuntu2504:6817`
- worker: `PC-210` / arm64 / macOS
- Slurm: `26.11.0-0rc1`
- 現在のproduction状態: controller/Macともoriginal local構成へ復旧済み
- 未適用変更: macOS configless FD修正はbuild artifactまで（production未導入）

## 目的

Macのlocal `-f`起動を`--conf-server=ubuntu2504:6817`へ切り替え、controller正本から
`slurm.conf`、`gres.conf`等を取得して登録、Job、GRES、reconfigure、復旧を確認する。

## source / bundled documentation確認

同梱の`doc/html/configless_slurm.shtml`では、controller側の
`SlurmctldParameters=enable_configless`と、worker側の`--conf-server`を要求している。
取得した設定は`SlurmdSpoolDir/conf-cache`へ保存され、`/run/slurm/conf`から参照される。
対応する配布対象には`slurm.conf`と`gres.conf`が含まれる。

## 構成差分preflight

Mac local configは次のmacOS対応値を持つ。

```text
ProctrackType=proctrack/pgid
TaskPlugin=(未指定、task/none)
JobAcctGatherType=jobacct_gather/none
SlurmdSpoolDir=/var/spool/slurmd
SlurmctldParameters=enable_configless
```

一方、2026-09-12にUbuntu controller正本で確認されたglobal値は次のとおりである。

```text
ProctrackType=proctrack/cgroup
TaskPlugin=task/affinity
MpiDefault=none
```

`proctrack/cgroup`はcgroupを持たないmacOSでは利用できず、`task/affinity`も本検証で
期待非対応として分離している。configlessはcontrollerのglobal `slurm.conf`を取得するため、
現在のままMacを切り替えると、既に検証済みのmacOS safe profileを維持できない。

## 判定

controllerはconfigless配布を有効化済みだが、配布されるglobal plugin profileがMacと非互換である。
本番slurmdを停止して失敗を再現する価値はなく、SMD-404を
`PREREQUISITE_MISMATCH_CONTROLLER_CONFIG`として停止する。

## 追加source調査

`src/slurmd/slurmd/slurmd.c::_establish_configuration()`の実装では、設定sourceの優先順位は
`--conf-server`、`SLURM_CONF_SERVER`、local file、DNS SRVであり、`--conf-server`を指定した
slurmdはlocal `-f`や`SLURM_CONF`よりcontroller取得を優先する。取得後はcontrollerから得た
`SlurmdSpoolDir/conf-cache`へ全対応fileを書き、そこにある`slurm.conf`をdaemon自身と
slurmstepdへ渡す。

`ProctrackType`、`TaskPlugin`、`JobAcctGatherType`はいずれもglobal設定で、NodeName単位の
plugin overrideは実装・man pageに存在しない。一方、`ProctrackType`を未指定にした場合だけは
compile時の`WITH_CGROUP`により既定値が分岐する。

```text
Linux WITH_CGROUP: proctrack/cgroup
macOS without cgroup: proctrack/pgid
TaskPlugin unset: no task plugin
JobAcctGatherType unset/none: no jobacct gather plugin
```

このため一時的な共通profileは、3つのglobal行を削除することで構成できる。Linuxは
`ProctrackType`だけcgroup defaultを維持するが、`task/affinity`と
`jobacct_gather/cgroup`は試験中無効になる。Ubuntu workerのtask bindingとtask-level
accountingが一時的に低下するため、controller正本の変更前後でUbuntu単体およびmixed-node
回帰を必須とする。

## macOS runtime path defect

同梱実装はconfigless cacheへのlinkを`/run/slurm/conf`へ固定していた。しかし実機では
`/run`が存在せず、root filesystemはsealed/read-only APFSである。書込み可能なruntime
directoryは`/var/run`（実体`/private/var/run`）であり、既存のmacOS SACK対応も
`SLURM_SACK_RUN_DIR=/var/run`を使用している。

このため、SACKとconfiglessが同じplatform runtime rootを使うよう限定修正した。

- `src/common/sack_api.h`: `SLURM_CONFIGLESS_RUN_DIR`、`CONF_DIR`、`CONF_FILE`を定義。
- `src/slurmd/slurmd/slurmd.c`: cache symlinkをplatform pathに作成。
- `src/common/read_config.c`: user commandのcache探索を同じplatform pathへ統一。
- `doc/html/configless_slurm.shtml`: macOSでは`/var/run/slurm/conf`であることを追記。

Linuxでは既存の`SLURM_SACK_RUN_DIR=/run`を使うため、従来の
`/run/slurm/conf`から変更しない。
