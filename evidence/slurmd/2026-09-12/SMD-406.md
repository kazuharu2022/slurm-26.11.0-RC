# SMD-406 IPv6

- 状態: `PASS`
- controller: `ubuntu2504` / x86_64 / Ubuntu 24.04
- worker: `PC-210` / arm64 / macOS
- Slurm: `26.11.0-0rc1`
- 現行production通信: IPv4

## 目的

Slurmのcontroller、worker、client、accounting経路をIPv6で構成し、node登録、CPU Job、
GPU Job、interactive step、accounting、復旧をIPv4構成と同じ基準で確認する。

## 既知の前提不足

先行preflightでは、Mac en0にはscope付きlink-local IPv6しかなく、Ubuntu側にも両host間で
名前解決・route可能なglobal/ULA IPv6が確認できなかった。link-localはhostごとにinterface
scope名が異なり、単一のSlurm正本で安定したNodeAddr/SlurmctldHostとして使うには追加設計が
必要なため、runtime試験の前提とは扱わない。

Slurm同梱文書`doc/html/network.shtml`では次を要求している。

- 既定はIPv4。
- `slurm.conf`と`slurmdbd.conf`に`CommunicationParameters=EnableIPv6`を設定する。
- IPv4を無効化する場合は両方に`DisableIPv4`も設定する。
- daemonを再起動する。
- nodeは`getaddrinfo()`が最初に返す単一addressへmapされる。

したがって、アドレスを用意するだけでなく、名前解決順序、6817/6818/6819のlistener family、
slurmdbdとの通信、Job中の実peer addressもEvidenceに含める。

## Read-only preflight

次の2本を追加した。

- `smd406_macos_ipv6_preflight.sh`
- `smd406_ubuntu_ipv6_preflight.sh`

両scriptはproduction設定、network、daemon、Jobを変更しない。次を採取する。

- global/ULA IPv6 addressとroute
- peer名のIPv6解決
- 6817/6818/6819 listener
- `CommunicationParameters`
- controller、node、queue、service/PID
- production fileのbefore/after SHA-256

両hostで固定global/ULA、相互route、名前解決が確認できない場合は
`MISSING_ROUTABLE_IPV6`で停止する。その場合の次候補は、同一L2上のUbuntu `br0`とMac
`en0`へ専用ULA `/64`を一時追加し、試験専用の名前/addressを使う方式である。この操作は
network interface、`/etc/hosts`、Slurm設定、daemonを変更するため、preflight Evidenceと
復旧設計を提示した後に別途明示承認を得る。

## ULA network Attempt 1: default-route比較で停止

Ubuntu `apply`はdriver hash一致後に開始し、`br0`へULAを追加した後、IPv6 default routeの
before/after完全一致比較で停止した。

```text

recovery: removed temporary Ubuntu ULA=fd40:534d:4406:1::180/64 interface=br0
```

この時点ではstate fileを作成していないため、後続の手動`restore`が
`missing active state: /run/smd406-ubuntu-ula.env`となるのは設計どおりである。二重障害や
復旧失敗ではない。EXIT trapによるaddress削除markerがあり、Mac probe、Slurm config変更、
daemon再起動、Jobには進んでいない。

現段階では、IPv6 default routeが意味的に変わったのか、Router Advertisement由来の
`expires`等の可変表示だけが変わったのかは未確定である。apply run directory内の
`default-ipv6-before.txt`と`default-ipv6-applied.txt`、addressとroute Evidenceを読み戻して
からdriver判定を修正する。推測だけで再実行しない。

### Attempt 1 readbackと原因確定

readbackではIPv6 default routeのgateway、interface、protocol、metric、hoplimit、preferenceが
同一で、RA lifetimeだけが`expires 3582sec`から`3579sec`へ3秒減少していた。IPv4 default
routeのdiffは空であった。これはULA追加による意味的なdefault route変更ではなく、時間経過で
必ず変わるRA lifetimeを完全一致比較したdriverのfalse positiveである。

追加中はUbuntu ULAが`scope global`、Mac候補へのrouteが`dev br0`、sourceがUbuntu ULAに
なっていた。cleanup後はULA残留なし、state fileなし、production hash diffなし、3 service
active、両node IDLE、allocation 0、queue空を確認した。よってauto recoveryはPASSであり、
Slurm/networkのproduction障害ではない。

driverはraw routeをそのまま保存しつつ、判定時だけ`expires <秒>sec`を除外したsemantic fileを
比較するよう修正した。gateway、interface、protocol、metric、hoplimit、preference等の差は
引き続きFAILとなる。実測2行を用いたfixtureでsemantic比較PASS、`/bin/sh -n`、未承認exit 64、
whitespace checkを再確認した。

- 修正版Ubuntu control SHA-256:
  `78be3cc8bb50de5d163055d217ad327bcdaa1f51d4d963f8b714dea321fbf961`

修正版の再実行はAttempt 1の承認範囲を自動延長せず、別承認待ちとする。

## Slurm IPv6 runtime preflight driver

一時ULA network Phaseの完了後、productionを変更しない次段階として、実際のSlurm IPv6
runtime試験に必要な両host用read-only preflight driverを追加した。

- `contribs/macos-tests/smd406_macos_runtime_preflight.sh`
- `contribs/macos-tests/smd406_ubuntu_runtime_preflight.sh`

候補構成はIPv4を維持したまま、次の差分だけを`/tmp`配下へ生成する。


Mac driverはcandidate `slurm.conf`を`slurmd -C`と`slurmd -G`で読み、hardwareとApple GPU
GRESの解析まで行う。Ubuntu driverはcandidate `slurm.conf`を`slurmd -C`で読む。

IPv4 recovery pathを残す。IPv6-onlyの証明は初回runtime成功後の別承認Phaseとする。

`e11eb37622556c77e7821c18f67bb37fb06cf6aeaa8cc219c74b50c7418891ca`と一致した後、

### wire address-family修正

`slurm_pack_addr()`はOSのnative値をwireへ直接出さず、既存Linux互換の固定値
`IPv4=2`、`IPv6=10`へ変換するよう修正した。`slurm_unpack_addr_no_alloc()`はwire値2/10を
各OSの`AF_INET`/`AF_INET6`へ戻す。Linux同士の既存wire formatは変えず、DarwinとFreeBSD等で
native `AF_INET6`値が異なる場合だけ正規化する。
