# SMD-401 PMI2 / PMIx / MPI

- 状態: `PASS_SINGLE_NODE_PMI2_PMIX_OPENMPI / MPIRUN_ALLOCATION_ONLY_ACCOUNTING`
- 対象: Apple M5 Max / arm64 / macOS上の`slurmd`・`slurmstepd`
- Slurm: `26.11.0-0rc1`
- test user: `testuser`（UID/GID 3001:3001）
- production変更: PMIx plugin配置と`slurmd`単体再起動
- package追加: ユーザー実施のPMIx 6.1.0 / libevent 2.1.13を使用

## Research Question

macOS workerでSlurm同梱のPMI2 client APIと`mpi/pmi2` pluginを使い、単一nodeの
4 taskが同じPMI2 namespaceへ参加し、rank情報とKVS値を共有できるか。またPMI2 stepを
cancelしたときに全task、step、割当資源が回収されるか。

PMIxと外部MPI implementationは別の事前条件を持つため、PMI2 API probeの成功だけで
PMIx/Open MPI/MPICH対応までPASSとはしない。

追加Research Questionとして、PMIx 6.1.0と`mpi/pmix_v6`を使う単一node 2 taskが
同じnamespaceへ参加し、rank 0の値をFence後に共有できるか、cancel時にtask/step/資源を
回収できるかをPMI2とは分離して検証する。

外部MPIの追加Research Questionとして、arm64 Open MPI 5.0.11の2 rankがローカルPRRTEと
PC-210限定のSlurm `--mpi=pmix_v6` direct launchの双方でbroadcast、all-reduce、
point-to-point通信を完了できるか、また通信後のcancelでtask/step/資源を回収できるかを検証する。
`mpirun`をSlurm allocation内で使う経路とmulti-node MPIは別範囲とする。
