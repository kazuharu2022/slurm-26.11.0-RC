# SMD-403 `scrun` / OCI container preflight Evidence

日時: 2026-09-24 15:04–15:08 JST

最終状態:

```text
BLOCKED_SAFE_PRECONDITION / NATIVE_MACOS_OCI_RUNTIME_UNAVAILABLE
```

## Research Question

現在のUbuntu controller/workerとMac arm64 workerで、productionを変更せずにSMD-403の
`scrun` / OCI container runtime試験を開始できるか。

成功試験の前提は次のとおり。

- `scrun`を使う経路では、Linux build、Lua、`scrun.lua`、公式例が要求するMUNGE認証
- `srun --container`を直接使う経路では、compute node上で動くrootless OCI runtimeと`oci.conf`
- OCI bundleをcompute nodeから参照できること
- container lifecycle、stdio、終了、cancel、cleanupをSlurm jobと対応付けられること

このpreflightではpackage install、MUNGE key読取/配布、config変更、daemon再起動、job投入、
container実行を行わない。

## 公式仕様とsource gate

公式Containers Guideは、host kernelとOCI runtimeの準備、compute nodeから参照できる
`oci.conf`、OCI bundle、Slurm外でのruntime直接動作確認を先に要求する。またcontainerは
rootless実行で、`oci.conf`がないexecution nodeではcontainer requestは実行されない。

Podman/Dockerと`scrun`を統合する公式例は、`AuthType=auth/munge`、`scrun.lua`、`oci.conf`を
前提とする。一方、`srun --container`によるdirect OCI runtime経路そのものについて、MUNGEは
一般要件として記載されていない。従来の「OCI全体がMUNGE必須」という表現を、`scrun`統合の
要件へ限定して訂正する。

参照した公式文書:

- https://slurm.schedmd.com/containers.html
- https://slurm.schedmd.com/scrun.html
- https://slurm.schedmd.com/oci.conf.html


## 分析

確認できた事実:

1. native Mac buildではsource条件により`scrun`がbuild対象にならない。
2. Mac hostにはSlurmが直接呼べるnative rootless OCI runtimeとLinux namespace/cgroup interfaceがない。
3. Docker DesktopのLinux VM engineは存在するが、Mac `slurmstepd`のnative OCI runtimeではない。
4. 両hostとも`oci.conf`がなく、container executionは有効化されていない。
5. UbuntuにはMUNGE、Docker、containerd、runc、Apptainerがあるが、`scrun`/Lua buildとrootless
   user namespace前提が不足する。
6. production clusterは`auth/slurm`であり、公式`scrun` integration例の`auth/munge`ではない。

以上から、native macOS workerでSMD-403の成功条件を測定できる状態ではない。packageを追加する
だけでは解決せず、Linux VM/別Linux workerをexecution nodeにする設計へ変える必要がある。

## 次の選択肢と停止条件

### A. native macOS SMD-403を非対応境界として閉じる

本preflightを最終境界とし、macOS native container lifecycleは未測定・非対応と記録する。
Docker Desktop内のLinux container成功をmacOS `slurmd`成功へ読み替えない。

### B. Ubuntu-only direct OCI extension

別試験としてUbuntu nodeだけを対象に、rootless user namespaceを安全に成立させ、Slurm外でruntime
direct testをPASSさせた後、限定`oci.conf`、OCI bundle、`srun --container`の順に検証できる。
この経路は`scrun`/MUNGE切替を必須としないが、SMD-403のmacOS成功にはならない。sysctl変更、
`oci.conf`配置、slurmd reconfigure/restart、job投入は別承認とする。

### C. Ubuntu-only `scrun` integration

Lua development filesを含むLinux Slurm build、`scrun.lua`、`oci.conf`、公式例に沿ったMUNGE認証、
container engine設定が必要である。production cluster全体のauth切替を伴う案はMac側MUNGE build、
daemon/key配布、全Slurm daemonの協調再起動を要し、なおMac上のnative OCI runtime不足は解消しない。
macOS検証を目的とする限り採用しない。
