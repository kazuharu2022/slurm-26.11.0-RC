# SMD-207 GPU反復安定性

- 状態: `PASS`
- 対象: Apple M5 Max / arm64 / macOS worker PC-210
- Slurm: `26.11.0-0rc1`
- GPU tool: 既存MLX 0.32.2 smoke job
- production設定変更: なし

## Research Question

Slurm GRES `gpu:apple:1`を通じて同一条件のMLX GPU jobを30回連続実行したとき、job failure、
GPU result failure、GRES/step残留を起こさず完走し、実行時間の分布とmacOSが公開するthermal状態を
再現可能なEvidenceとして残せるか。

## 測定境界

ローカルpreflightで`powermetrics --help`を確認すると、この環境は`thermal` samplerを
「thermal pressure notifications」、`gpu_power` samplerをGPU power/frequency情報として公開する。
一方、man pageに記載が残る`smc`を実際に指定すると`unrecognized sampler: smc`となった。

したがって、Apple M5 Maxの絶対温度（℃）を標準`powermetrics`経路から取得できるとは扱わない。
driverはrootで同じcapability probeを保存し、℃は`NOT_AVAILABLE`、代替観測値としてthermal pressureと
GPU power/frequencyのraw sampleを保存する。温度を推定・捏造しない。

## 固定条件

- 反復回数: 30（環境変数で増加可能、30未満は拒否、最大100）
- 各job: 1 node、1 task、2 CPU、4 GiB、`gpu:apple:1`
- workload: MLX float16 4096×4096 matrix multiplication、warm-up後5 iteration
- user: `testuser` UID/GID 3001:3001
- 実行方式: 逐次投入。競合試験ではなく、同一条件の再現性と資源回収を測る
- thermal sampler: `powermetrics thermal,gpu_power`、1秒間隔

## 成功条件

1. 30/30 jobとbatchが`COMPLETED 0:0`で、generic/typed GPU ReqTRES/AllocTRESを持つ。
2. 全jobがarm64、Apple M5 Max、MLX GPU device、`SLURM_JOB_GPUS=0`、smoke PASSを記録する。
3. `elapsed_seconds`を30件保存し、平均、中央値、母標準偏差、CV、最小、最大を算出する。
4. thermal pressureとGPU power/frequencyのraw sampleを保存する。℃の非提供もcapability結果として残す。
5. 終了後node IDLE、CPU/memory/GPU割当0、queue・slurmstepd・test process残留0となる。
6. slurmd PIDと入力config/job script hashが不変である。

crashなしは成功条件だが、実行時間に事前の性能閾値は設けない。外れ値は実測後に分布から記述し、
試験後に都合のよい閾値を作って除外しない。

## 実測結果 — PASS

2026-09-11 23:24～23:25 JST、Job 414～443を30件逐次実行した。30件すべてで
MLX 0.32.2、arm64、Apple M5 Max、`Device(gpu, 0)`、`SLURM_JOB_GPUS=0`、
`gpu_smoke_test=PASS`を確認し、stderrは全件0 byteだった。job/batch accountingも
30/30件が`COMPLETED 0:0`で、jobのReqTRES/AllocTRESにはgeneric/typed GPU各1が記録された。
失敗率は0%である。

測定対象の`elapsed_seconds`は平均0.015177秒、中央値0.014502秒、最小0.014361秒、
最大0.026655秒、母標準偏差0.002493秒、CV 16.428%だった。30値は一切除外していない。
Tukey法による探索的判定では上側fence 0.014649秒を超える6件が外れ値候補となった。
特にJob 415は中央値より83.802%、Job 423は49.435%長かった。

ただし、最初の5件平均0.016911秒に対して最後の5件平均は0.014508秒で、今回の短い連続試験では
反復に伴う進行的な遅延増加は観測されなかった。短時間kernelの外れ値原因は測定していないため、
OS scheduling、GPU、thermalなど特定の原因へ帰属しない。

`powermetrics`は23:24:06～23:25:32に1秒間隔で87 sampleを保存した。thermal pressureは
87/87が`Nominal`、GPU powerは0～1346 mW（平均373.793 mW）、GPU active frequencyは
0～957 MHz（平均466.368 MHz）だった。`smc` samplerは`unrecognized`のため絶対温度℃は
`NOT_AVAILABLE`であり、温度値を推定していない。約15 msの測定kernelと1秒sampleは時間分解能が
異なるため、個々のjob時間とpower sampleの直接相関は主張しない。

最終状態はlaunchd running/PID 94504、controller UP、node IDLE、CPU/memory割当0、AllocTRES空、
queue 0、slurmstepd・powermetrics・test process残留なしだった。slurmd PIDとinput hashも不変だった。
以上から、定義した30回の機能安定性と資源回収条件を満たしたためSMD-207を`PASS`とする。

Evidence: [`SMD-207-pass.txt`](SMD-207-pass.txt)

## 残る制約

- 長時間連続GPU負荷や高温環境でのthrottling（今回の短いsmoke 30回とは別試験）
- Apple内部センサーの絶対温度（標準sampler非提供のため`NOT_AVAILABLE`）
- 外れ値候補6件の原因分離。1秒power sampleは約15 ms kernelと直接対応しない
- 同一mean値は再現性Evidenceであり、CPU referenceとの数値correctnessはSMD-208で検証する
